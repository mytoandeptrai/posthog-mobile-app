## Stack

Expo Router app (Expo SDK 54, installed `54.0.37`) built as a **pure React Native** e-commerce learning demo. There is no WebView / DOM-component layer — every screen is native RN (`View`, `Text`, `Pressable`, `FlatList`, `TextInput`). Styling is plain `StyleSheet.create` against the shared tokens in `src/lib/theme.ts` (no Tailwind/NativeWind). State is 100% local/mock — no backend, no real network calls; auth and checkout are simulated with `setTimeout`.

The project's main purpose is to demonstrate **PostHog product analytics in React Native** (`posthog-react-native`): screen tracking, custom events, `identify`/`reset`, and feature flags.

Package manager is **pnpm** (`pnpm-lock.yaml`).

**Docs version note:** `AGENTS.md` says to read Expo docs pinned to v57, but the installed version is `~54.0.0` (see `package.json`/`node_modules`). Use https://docs.expo.dev/versions/v54.0.0/ instead — the v57 reference is stale.

## Commands

```sh
pnpm install
pnpm start              # expo start — dev server (native + web)
pnpm ios                # expo run:ios
pnpm android             # expo run:android
pnpm web                 # expo start --web
pnpm deploy              # exports web build then runs `eas-cli deploy`
```

Typecheck with `npx tsc --noEmit`. There is no lint or test script defined in `package.json`, and no automated test suite exists in this repo.

**Typed routes gotcha:** `app.json` has `experiments.typedRoutes: true`, so `expo-router` typed `href`s are validated against `.expo/types/router.d.ts`. That file is only regenerated by a running Metro instance (`expo start` or `expo export`), not by `tsc` alone — after adding/renaming/removing a route file, run `pnpm start` (or `npx expo export -p web`) briefly before trusting `tsc --noEmit` route-typing errors.

## Architecture

### Routing (`src/app/`)

- `_layout.tsx` — root `Stack`. Initializes the PostHog client (`export const posthog = new PostHog(...)`), wraps everything in `PostHogProvider`, `AuthProvider`, `CartProvider`, and auto-tracks screen views via `usePathname()` → `posthog.screen(pathname)`. Registers `(tabs)` (no header), plus stack screens for `login` (modal), `product/[id]`, `search`, `cart`, `checkout`.
- `(tabs)/_layout.tsx` — bottom `Tabs`: **Home** (`index.tsx`) and **Profile** (`profile.tsx`). Home's header carries the search icon and the cart icon/badge (`src/components/CartButton.tsx`).
- `login.tsx`, `search.tsx`, `product/[id].tsx`, `cart.tsx`, `checkout.tsx` — pushed from the root stack, not nested under `(tabs)`.

Navigation flow: Home/Search → `product/[id]` → Add to Cart / Buy Now → `cart` → `checkout` → complete → `router.replace('/(tabs)')` (replace, not push, so Back can't return to a completed order).

### State (`src/context/`)

- `CartContext.tsx` — `items`, `addToCart`, `removeFromCart`, `updateQuantity`, `clearCart`, derived `totalAmount`/`itemsCount`. Plain `useState`, in-memory only (no persistence).
- `AuthContext.tsx` — `user`, `isAuthenticated`, `loginDemo(name, email)` (simulated via `setTimeout`), `logout`.

Both providers wrap the app in `src/app/_layout.tsx`; consume via `useCart()` / `useAuth()`.

### Mock data (`src/data/products.ts`)

Static `Product[]` array (no `image` URLs — each product has an `icon` (`Ionicons` glyph name) + `color`, rendered by `src/components/ProductThumbnail.tsx` as a tinted icon tile). This avoids any network image fetches, keeping the app fully offline/mock.

### UI primitives (`src/components/ui/`)

`Button`, `Card`, `Badge`, `Input` — small `StyleSheet`-based primitives, not a generated component library. Feature-level composites (`ProductCard`, `CartItemRow`, `QuantityStepper`, `RatingStars`, `ProductThumbnail`, `CartButton`) live directly under `src/components/`.

### PostHog integration

- Client + provider setup: `src/app/_layout.tsx`.
- Per-screen events use `usePostHog()` from `posthog-react-native` and `.capture(...)`, e.g. `product_list_viewed` (Home), `product_searched` (Search, debounced), `product_detail_viewed` / `cart_item_added` (Product detail), `checkout_started` (Cart), `order_completed` (Checkout), `app_error_triggered` (Profile).
- Feature flags: `useFeatureFlag("show-promo-banner")` gates the Home promo banner; `useFeatureFlag("checkout-v2")` switches the Checkout screen between a plain address form (V1) and one with an added discount-coupon field (V2). `useFeatureFlags()` powers the "active feature flags" debug list on Profile.
- Identity: `login.tsx` calls `posthog.identify(userId, { email, name, plan })` then `posthog.reloadFeatureFlags()` after a successful demo login; Profile's Logout calls `posthog.reset()`.

These flag keys (`show-promo-banner`, `checkout-v2`) must exist in the connected PostHog project for their branches to activate — `useFeatureFlag` returns `undefined` until then, which the code treats as "flag off".

### Path alias

`@/*` maps to `src/*` (`tsconfig.json`).
